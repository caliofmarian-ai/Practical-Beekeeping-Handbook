# Visual System Reconciliation v1

## Purpose

This specification governs the final full-book visual reconciliation pass. Figma, Canva, SVG generation, illustration tools and photography are production methods only; they must not create competing visual languages.

## Canonical result

Every final asset must conform to one handbook visual system:

- one semantic colour palette;
- one typography hierarchy;
- one line-weight family;
- one arrow/callout grammar;
- one spacing and card system;
- one icon and object style;
- one set of master biological/mechanical reuse families;
- one accessibility model;
- one provenance and rights model.

## Reconciliation order

1. inventory every final visual asset;
2. group repeated concepts into master families;
3. detect style drift by wave/tool/source;
4. normalise semantic colour use;
5. normalise typography and line weights;
6. normalise recurring objects and biological anatomy;
7. eliminate duplicated/inconsistent redraws;
8. verify greyscale meaning;
9. verify print-size and digital legibility;
10. verify SVG/title/desc or equivalent accessibility metadata;
11. verify rights/provenance;
12. update galleries/manifests;
13. run final PDF/EPUB proof.

## Tool-neutral rule

No final page should visibly look “Figma”, “Canva” or “generated SVG”. Tool origin must disappear into the single handbook system.

## Colour

Use the semantic palette already defined in `VISUAL_STYLE_GUIDE.md`. Colour must never be the only carrier of meaning. Greyscale must preserve interpretation through labels, shapes, borders, icons and line styles.

## Final gate

No visual system is considered publication-ready until the reconciliation report confirms PASS across the complete book, not only individual waves.
