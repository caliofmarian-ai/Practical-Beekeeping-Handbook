# Illustration Style Guide

**Project:** Practical Beekeeping Handbook  
**Version:** 1.1  
**Status:** Active editorial standard

## Purpose

Illustrations must improve understanding. They should explain structures, processes, equipment, decisions, or biological concepts that are difficult to communicate using text alone.

Illustrations are educational assets, not decorative fillers.

## Approved Visual Types

- Technical line drawings
- Labelled biological illustrations
- Hive cross-sections
- Equipment diagrams
- Process diagrams
- Decision trees
- Seasonal calendars
- Infographics
- Maps
- Comparison graphics
- Workflow illustrations
- Original annotated photographs

## Core Visual Style

All illustrations should be clear, accurate, practical, uncluttered, readable on a phone, readable in print, and visually consistent.

Avoid excessive shadows, unnecessary gradients, crowded backgrounds, ornamental borders, tiny labels, ambiguous symbols, and unrealistic hive or bee anatomy.

## Technical Accuracy

Every technical illustration must be checked against the final text. Labels must use the same terminology as the chapter.

Dimensions, proportions, directions, and component relationships must be realistic unless the visual is marked:

> Simplified diagram — not to scale.

## Bee Anatomy

Bee anatomy illustrations should identify the caste shown, use accurate proportions, distinguish queen, worker, and drone where relevant, label structures consistently, and avoid exaggerated cartoon anatomy.

## Hive and Equipment

Hive illustrations should clearly distinguish the cover, supers, brood chamber, frames, foundation, floor, entrance, stand, ventilation, and insulation where relevant.

Units must be consistent. Compatibility between hive systems must not be implied unless verified.

## Diagrams and Workflows

Use a clear reading direction: top to bottom or left to right.

Use consistent symbols:

- Rectangle: action
- Diamond: decision
- Arrow: direction
- Warning symbol: hazard
- Check mark: acceptable condition
- Cross mark: unacceptable condition

## Labelling

Labels must be short, unambiguous, readable, and consistent with the text. Avoid unexplained abbreviations. Leader lines must point precisely to the intended structure.

## Numbering

Use chapter-based numbering:

- Figure 1.1
- Diagram 4.1
- Map 8.1
- Plate 12.1

The first number identifies the chapter. The second identifies the sequence within that chapter.

## Captions

Every visual must include:

1. Visual type and number
2. Concise title
3. Practical explanation
4. Scale note when relevant
5. Attribution or licence when required

Example:

> **Figure 5.2 — Main components of a vertical movable-frame hive.**  
> Simplified cross-section showing the floor, brood chamber, honey super, inner cover, and roof. Not to scale.

## File Naming

Use lowercase names with hyphens.

Examples:

```text
figure-01-01-basic-hive-components.svg
diagram-06-02-swarm-capture-process.svg
photo-10-03-capped-honey-frame.jpg
```

Avoid vague names such as `image1.jpg`, `newdiagram.png`, or `final-final-version.svg`.

## File Formats

- SVG for diagrams and line drawings
- PNG for transparent raster graphics
- JPG or JPEG for photographs
- WebP only for web-specific exports
- PDF only for print-ready vector assets when necessary

Keep editable source files whenever possible.

## Resolution

For print, photographs should normally be at least 300 dpi at final size. Line art should preferably be vector-based.

For digital editions, optimise images without destroying detail or readability.

## Colour and Grayscale

Illustrations must remain understandable in grayscale. Do not use colour as the only way to communicate meaning.

## Accessibility

Every important image must have descriptive alt text, a meaningful caption, sufficient contrast, and an explanation in the surrounding text.

## Originality and Licensing

Original illustrations are preferred.

Externally sourced material may be used only when the licence permits commercial use, attribution requirements are followed, and the source is documented.

Do not use images merely because they are visible online.

## AI-Assisted Images

AI-assisted illustrations require careful human review.

Reject or correct images containing incorrect bee anatomy, impossible hive geometry, duplicated body parts, unreadable labels, invented equipment, misleading scale, or unrealistic comb structure.

## Storage Structure

```text
assets/
├── illustrations/
│   └── chapter-01/
├── diagrams/
│   └── chapter-01/
├── photos/
│   └── chapter-01/
└── icons/
```

Retain editable source files where possible.

## Review Checklist

- [ ] Clear educational purpose
- [ ] Technical content is accurate
- [ ] Terminology matches the text
- [ ] Labels are readable
- [ ] Numbering is correct
- [ ] Caption is complete
- [ ] Works in grayscale
- [ ] File name follows the standard
- [ ] Resolution is sufficient
- [ ] Alt text is available
- [ ] Licensing is documented
- [ ] Source file is retained where possible

## Approval Rule

An illustration is complete only when the visual file exists, caption and alt text are written, technical accuracy has been reviewed, licensing is documented, and the figure is referenced in the chapter text.
